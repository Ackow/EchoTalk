EchoTalk 2.0 开发文档

面向参与开发的工程师：环境搭建、日常工作流、编码约定、场景包开发指南、API 接口契约、数据库模型、测试与排错。

v2.0.0 更新 2026-09-28 FastAPI + MySQL + Vue 3 + Electron 架构与接口契约 → 技术文档

01环境要求

依赖版本用途
Node.js≥ 18前端构建与 Electron
Python3.12（>=3.12,<3.13）后端运行时
uv最新Python 依赖管理（锁文件 uv.lock）
MySQL 8utf8mb4业务数据库，本地约定端口 3307
!

仓库根目录的 .venv/ 是 1.0 旧环境，不要激活；2.0 后端环境固定在 backend/.venv（由 uv 创建）。

02快速开始

2.1数据库

SQL
CREATE DATABASE echotalk CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'echotalk_app'@'%' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON echotalk.* TO 'echotalk_app'@'%';
FLUSH PRIVILEGES;

云数据库同理：在服务商控制台建库授权即可，后端不负责创建 MySQL 实例本身。

2.2后端

Bash
cd backend
cp .env.example .env          # 填写 ECHOTALK_DB_PASSWORD（必填，缺失直接拒绝启动）
uv sync --locked --cache-dir .uv-cache
uv run --cache-dir .uv-cache python init_db.py    # 显式建表 + 同步 4 个内置场景种子
uv run --cache-dir .uv-cache python main.py       # http://127.0.0.1:8000
  • init_db.py 是显式建表步骤：API 启动不会自动执行 DDL；表未建时启动只告警（内置种子同步跳过）。
  • 验证：curl http://127.0.0.1:8000/api/ready → {"status":"ready"}。

2.3前端（浏览器开发）

Bash
cd frontend
cp .env.example .env.local    # 本地开发默认指向 127.0.0.1:8000，可不改
npm ci
npm run dev                   # http://127.0.0.1:5173

2.4前端（Electron 桌面开发）

Bash
cd frontend
npm run electron:dev          # concurrently 拉起 Vite + wait-on 后启动 Electron

桌面端开发时后端仍需单独终端启动。生产打包见 §11 构建与部署。

05日常开发工作流

改后端代码
uvicorn 带 --reload，保存自动重启；若行为异常，kill 端口进程重启（见 §12 排错）
数据库结构变更
改 app/models.py 后：开发期可 drop 相关表重跑 init_db.py（注意会清数据）；正式迁移脚本体系后续引入，改表前先备份
改前端
Vite HMR 实时生效；构建检查用 npm run build
新增场景 API
按「endpoints（解析/响应）→ services（业务）→ scenes|models（数据）」分层；接口清单见 §8.3 接口总表。静态路由注册在 /{scene_id} 之前（scenes.py 内有注释说明顺序约束）
改 package_json 结构
必须同步改 scenes/schema.py 校验 + registry.apply_package 冗余列 + registry.summary 摘要，并跑 §10 冒烟
新增错误
继承 AppError（或直接 AppError(msg, code=..., status_code=...)）；错误码全大写下划线，加入技术文档错误码表

06编码与协作约定

后端

  • 分层红线：控制器不写业务；服务层不 import fastapi（HTTP 类型只在 endpoints/deps）。
  • 注释与 docstring：中文、同行简洁；类保留一行 docstring，字段用行尾 # 说明。
  • 所有可预期错误走 AppError；响应只有 {"error": {code, message, details?}} 与 2xx 业务体两种形态。
  • 时间一律 UTC（core/timeutil.utcnow），序列化输出 ISO 字符串。
  • 写操作（创建/更新/删除/导入/发布）必须调用 registry.invalidate_cache()；提交前 db.flush() 依赖唯一约束兜底冲突。
  • 涉及 scene_user_stats/scene_stats 的计数变更放在同一事务提交，计数下限保护 max(0, n-1)。

前端

  • API 只经 src/api/*.js 封装，组件不直接 import axios；错误直接展示 err.message，需要分支判断时用 err.code（如 SCENE_ID_CONFLICT）。
  • 列表过滤/排序/分页用 computed 链（参考 Scenes.vue 的 filteredItems → sortedItems → pagedItems），不手动维护中间数组。
  • 新页面放入 AppShell 子路由 + ModulePlaceholder 占位先行；标题/描述写路由 meta。
  • 视觉令牌（主色 #6265E8、间距/圆角三档）统一走 assets/styles.css，不要在组件里散落硬编码色值。
  • 交互验收：UI 改动用浏览器实测（Electron 与 Web 双端），重点检查窄屏与游客态。

Git

  • 提交信息：中文，首行一句话概述 + 空行 + 分模块要点列表（参考 4e81702 的格式）。
  • 不提交：backend/.env、frontend/.env*（example 除外）、backend/storage/、.uv-cache、dist*。

07场景包开发指南（scene.yaml）

7.1字段速查

区块必填说明
meta✅id（^[a-z][a-z0-9_]{1,49}$，创建后不可改）、name、description、category（daily/business/career/academic/custom）、difficulty（entry/easy/normal/hard/expert）、mode（conversation/interview/debate）、version（种子刷新依据）、compat.min_app、tags
roles✅1–4 个：id、display_name、title、personality、voice/avatar（推荐值）、backstage（幕后角色如 Evaluator）
prompt✅system（模板，支持 {param} 与 {roles.<id>.<字段>}）、greeting、params（≤16，key/type/default/editable/tip）
objectives—≤8：id、label、skill（技能图节点）、check（表达式）
state✅初始任务状态（自由 JSON），根键将被目标/结束表达式引用
tools✅allowed ⊆ 9 个注册工具；config 键 ⊆ allowed
coordination—{order: [role_id]} 多角色协调（interview/debate 用）
stages—≤8：id、name、guidance、exit_when
finish✅when（表达式）、max_turns（2–200，默认 30）、on_finish（当前仅 request_feedback）
knowledge—files（≤20：path/visibility/sections）、retrieval.default_top_k
evaluation—dimensions（≤6：id/label/weight/source=state|llm/hints）、notes
guardrails—language、min_words、keyword_tips（match/tip）、off_topic（domain_keywords/action）、max_warnings_per_turn
avatar—preferred、rate（0.5–2.0）

完整示例见 backend/app/content/scenes/cafe_ordering.yaml；四步创建向导生成的即是同一结构。

7.2表达式可用语法

表达式 DSL
逻辑：a and b / a or b / not a
比较：==  !=  >=  <=  >  <  in
引用：state.order        # 包内声明的 state 根键
     state.order[0].size # 支持 . 与 [n]
     stage / stage_turns / turn_count   # 运行时保留键（不要在 state 里声明）
函数：tool_called('modify_order')       # 本轮是否调用过该工具
     state_changed('state.confirmed')  # 本轮该路径是否变化
     goals_done()                      # 全部带 check 的目标是否达成
字面量：true / false / null / 数字 / '字符串'
!

不支持：算术、属性访问、任意函数、关键字参数——校验期（POST /api/scenes/validate）就会报 SCENE_INVALID_EXPRESSION，并检查引用的 state 根键是否已声明。

7.3内置种子与版本

  • 种子文件放 backend/app/content/scenes/*.yaml，启动（startup 钩子）与 init_db.py 各同步一次。
  • 同步规则：不存在则插入（source=builtin）；已存在且 meta.version 更大则刷新——改内置种子必须 bump version。
  • 内置场景运行期只读（409），验证修改效果请「复制为自定义」或在创建向导里从模板创建。
  • 历史难度值（CEFR/中文）由 _migrate_difficulties 幂等迁移，无需手工处理旧数据。

08API 接口契约

8.1通用约定

  • Base URL：开发 http://127.0.0.1:8000，所有业务接口统一挂 /api 前缀；云端部署走 HTTPS 反代。
  • 鉴权：登录类接口返回 access_token，后续请求带 Authorization: Bearer <token>；令牌 30 天有效，仅当前端撤销。
  • 幂等性：每个请求由中间件分配/透传 X-Request-ID（12 位 hex）并在响应头回传，排障时按此对日志。
  • 响应只有两种形态：2xx 直接返回业务体，或 统一错误信封（见 8.2）；无第三种混合形态。
  • 前端超时 15s（导入/导出/资料上传 60s、封面 30s）；仅幂等 GET 在网络错误或 5xx 时重试，最多 3 次、退避 0.5s/1s/1.5s；4xx 一律不重试。
响应形态
# 成功（2xx）：业务体直接返回
{ "access_token": "…", "user": { … } }

# 失败：统一错误信封（details 为可选的字段级错误列表）
{ "error": { "code": "SCENE_ID_CONFLICT", "message": "…",
             "details": [ { "field": "…", "message": "…" } ] } }

Bash

  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d @scene.json
JSON · 422 校验失败
{

    "code": "SCENE_INVALID_PACKAGE",

  -H 'Authorization: Bearer <token>' -F 'file=@pkg.zip'
# → 201 { "scene": {…}, "action": "renamed" }（ID 自动变为 {id}_2、{id}_3…）

09数据库模型

MySQL 8（utf8mb4），共 7 张业务表；ORM 为 SQLAlchemy 2.x，引擎带 pool_pre_ping + pool_recycle=1800 防空闲断连；会话为请求级事务会话（finally 关闭）。

9.1表关系

ER 关系
users ──1:N── auth_sessions
  │
  └─1:N── scenes（author_id，builtin 为 NULL）──1:N── documents ──1:N── chunks
                │            │
                │            └──1:1── scene_stats（likes/downloads/favorites 计数）
                │            └──1:N── scene_user_stats（scene_id+user_id 唯一，一人一票）

usersusername(唯一)、password_hash账户
auth_sessionstoken_hash(唯一)、expires_at、revoked_at服务端会话；库中只存令牌 SHA-256 摘要
scenesid=meta.id（字符串主键）、package_json(完整包)、source(builtin/custom/imported)、status(private/published)、difficulty、cover_path、greeting_text、domain_keywords场景包；标量列为查询/展示冗余，package_json 是唯一事实来源
documentsscene_id(CASCADE)、filename、chunk_count、visibility(user/ai_only)资料元数据；源文件在 storage/
chunksdocument_id(CASCADE)、scene_id(冗余索引)、section、visibility、ordinal、text解析分块；向量索引为运行时产物（阶段 3）
scene_statsscene_id(主键)、likes、downloads、favorites聚合计数，惰性创建（首次互动才建行）
scene_user_stats(scene_id,user_id) 唯一约束、liked、favorited用户互动态，一人一票

文件存储（backend/storage/scenes/{scene_id}/，gitignore）：资料源文件在 knowledge/（.md/.markdown/.txt/.pdf，≤10MB），封面为 cover.*（.jpg/.png/.webp，≤5MB）。分块目标 700 字符、上限 1100，超长按空行段落二次切分。

9.3关键决策

  • package_json 存校验后模型的完整 dump（v1.6 修复）：此前存原始请求 dict，Pydantic 默认值（category/mode/version）不落库，导致编辑回显下拉为空、导出包不完整；现改为 model_dump() 完整落库，读写两端结构一致。
  • 难度五级英文枚举 entry/easy/normal/hard/expert（前后端契约）：校验器强制小写；种子同步时执行幂等迁移 _migrate_difficulties（历史 CEFR 按首字母 A→easy / B→normal / C→hard，中文三档直接映射，未知归 normal），冗余列与 package_json.meta.difficulty 同步刷新。
  • 变更 package_json 结构时必须同步三处（见 §5 工作流）；改表开发期可 drop 重跑 init_db.py（注意清数据）。
